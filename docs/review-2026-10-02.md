# Second-pass design review — 2026-10-02

Scope: product design, architecture, configuration proposal, roadmap, and existing scaffold. No new runtime behavior was implemented. MIT licensing was added separately at the owner's request.

## Verdict

Proceed with the read-only M1 probe. Do not treat the current architecture as proof that reliable bulk current-desktop tiling is feasible with public APIs. The decisive unknown is window visibility/identity correlation. Keep M2's first workflow to explicitly enrolled focused windows and require the experimental gates before mutations.

## Findings and disposition

| Priority | Finding | Resolution / remaining evidence |
| --- | --- | --- |
| High | Current-desktop discovery was described as available before AX/CG correlation was proven | Focused enrollment first; P1/P2 gate bulk enrollment and all write eligibility |
| High | Generations alone did not define pause, cancellation, or late-completion behavior | Separate epoch/revision/admission values; pause invalidates queued work, acknowledges already admitted IPC |
| High | Async coordination could still block or queue unbounded tasks | Dedicated worker ownership, bounded mailboxes, single drains, no AX on the actor executor |
| High | Coalescing could lose meaningful relative commands | Ordered command reduction; coalesce absolute frame targets only |
| Medium | Timeout propagation was underspecified | Explicit actual-handle or process-wide configuration; zero is not cancellation; measure via P3 |
| Medium | Control+Option overlaps the default VoiceOver modifier | No enabled defaults; optional Control+Shift example and mandatory conflict checks |
| Medium | JSON object bindings could hide duplicates before validation | List of bindings with normalized chord validation; no custom JSON parser or duplicate-member guarantee |
| Medium | Tree geometry was conflated with usable layout policy | Define enrollment/removal, focus selection, constraints, rounding, and depth limits before M2 |
| Medium | Multi-app partial writes and user drag had no explicit ownership rules | Keep successful results, stop bounded retries, yield on unexpected movement; no automatic rollback |
| Medium | Native desktop/display transitions were deferred too far | Epoch invalidation and conservative re-enrollment required before M2, broad compatibility remains M4 |
| Low | Documents still called the license undecided and hosting absent | MIT added; README, contribution guide, ADR and roadmap updated |

## Evidence checked

- Installed macOS 27 SDK `AXUIElement.h`: messaging timeout is per actual object unless set process-wide; equal AX objects do not inherit an individual override. Calls report unsupported, invalid-element, and messaging errors. [Apple API index](https://developer.apple.com/documentation/applicationservices/axuielement_h).
- Installed SDK `CGWindow.h`: public window IDs and on-screen list flags exist; this does not establish a public AX-to-CG identity bridge. [Apple window-list API](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)).
- [Apple VoiceOver documentation](https://support.apple.com/en-ca/guide/voiceover/vo2681/mac): Control+Option is a default modifier.
- [MIT license text](https://opensource.org/license/mit): standard grant and notice added to LICENSE.

SDK inspection establishes API contracts, not observed app behavior. No upstream source audit or AX experiment was performed in this review. Earlier concept-level inspiration notes remain valid; no upstream implementation was copied.

## Implementation order

1. Read-only process/window registry with typed outcomes and redacted diagnostics.
2. P1–P4 evidence and a bounded fake-worker harness.
3. Control state machine and admission/revision tests.
4. Single-desktop explicit enrollment and bounded frame application.
5. Input experiments, optional bindings, then wider daily-use hardening.
