# M1 read-only probe

Implemented on 2026-10-04. P1/P2 have partial user-reported observations and documented exclusions; P3 has a scoped real-AX fixture result. P4 has partial user-reported connection, negative-origin move, disconnection, and sleep/wake evidence; simultaneous mixed-scale coverage remains open. No window-manager reliability or current-desktop eligibility is claimed.

## Use

1. Run `scripts/verify`, then `scripts/package-app`, and open `dist/iTile.app`.
2. Choose **Enable Accessibility for inspection…** and enable the packaged app in macOS Accessibility settings. The app does not request Screen Recording or input monitoring. An ad-hoc rebuild may require granting Accessibility again.
3. Choose a running application under **Inspect application**. The report opens after the worker responds. Choose that application again to compare snapshots.
4. **Copy diagnostic report** explicitly copies the currently displayed text. Reports are otherwise in memory only. App names appear only in the local selection menu; reports omit them, titles, document paths, raw keys, and OS window IDs. Record exact tested app versions separately when writing an experiment report.
5. **Pause inspections** blocks new requests and rejects outstanding results. Resume does not trigger inspection. **Quit iTile** exits without joining blocked workers.

## Implemented behavior and limits

- The main thread snapshots displays and maintains application lifetimes using `NSRunningApplication` and termination notifications. A fresh attachment gets a new generation, including PID reuse. The menu discovers running regular applications when opened; window enumeration is explicit only.
- Each selected application owns one dedicated `Thread` and `CFRunLoop`. AX objects never cross that thread. A lock protects a single-request mailbox and wakeup handles; no lock is held during IPC. Idle run loops sleep until an observer notification or request. There is no periodic AX polling. Before each scan, notification draining is capped at 64 run-loop iterations; reaching the cap invalidates identity conservatively so notification traffic cannot indefinitely starve a request.
- At most 16 application workers are retained, until application termination or quit. A stuck worker remains busy and is never replaced for that live attachment. Idle retirement/backoff remains future work. Each snapshot admits at most 64 windows; extra requests while busy are rejected rather than queued.
- Each actual AX handle receives an experimental 0.2-second messaging timeout before attribute reads. A soft five-second scan budget is checked between windows. A window's remaining calls and cleanup may extend this budget; neither setting guarantees a hard deadline. P3 must establish practical behavior before these values become control defaults.
- Window identity uses AX equality within one process attachment. Destruction notifications invalidate the whole app registry conservatively. Missing windows are retired at the next snapshot. Unsupported destruction observation expires only the affected element’s token before the next snapshot. Each element reports its notification registration result; observer creation failure expires all tokens. Tokens are never derived from titles, and retired serials are never reused. This is a hypothesis to validate against native tabs and app-specific AX behavior, not proof against every stale-handle race.
- Failed enumeration, duplicate equal handles, window-limit overflow, or a partial timed-out scan invalidates identity. Missing/unsupported attributes remain `unknown(AX error)`; wrong types remain `unknown(type)`. Capability queries never execute the operation they describe.
- Space/display and sleep/wake notifications, pause/resume, and observed permission loss invalidate displayed and pending reports. The next inspection clears identity for the new environment epoch. Permission is checked on menu opening, request, worker entry, and delivery; there is no continuous trust polling. Reports are historical, non-atomic snapshots and do not automatically refresh on window changes.
- Source diagnostics now also read each window’s modal flag and scan at most 16 direct children for the public `AXSheet` role. Child handles stay on the worker, receive explicit timeouts, and respect the remaining soft scan budget. The report distinguishes observed sheet counts from incomplete scans. It never descends into sheet contents; nested sheets remain unchecked. User-supplied Chrome chooser reports showed one direct AXSheet while open and zero after cancellation, retaining the parent token. Nested sheets and broader dialog coverage remain untested.
- Reports include usable screen bounds transformed to top-origin logical points, scale factors, roles/subroles, minimized/fullscreen state, position/size, and whether position/size are settable. Only fixed role names are emitted; custom role strings are redacted. They do not enumerate every AX action or establish tiling eligibility.
- CG on-screen PID/layer/bounds metadata is listed separately. No AX-to-CG match, bulk enrollment, focus action, setter, hotkey, or automatic tiling is implemented. CG APIs can return other metadata internally; only the allowlisted numeric fields reach the report.

## Observed native-tab limitation

In the user-reported Finder tab-switch check on 2026-10-04, one standard-window token changed while its bounds, environment epoch, and sibling tokens stayed unchanged. Successful destruction-notification registration does not establish stable containing-window identity across native tabs. Keep fresh tokens and conservative retirement; do not correlate tabs by titles or identical bounds. These explicit observations do not implement automatic tab-transition detection or make future writes safe. See the timestamped evidence in [validation](validation.md).

## Observed dialog limitation

With Chrome’s file chooser requested open, the 2026-10-04 report listed only its standard main AX window while CG listed an additional surface. Top-level enumeration alone did not classify the chooser. Standard role and settable frame attributes therefore cannot establish absence of a blocking dialog. Bounded direct-child sheet/modal diagnostics subsequently detected one sheet while the chooser was open and zero after cancellation in user-provided reports. The parent remained modal=false throughout. Unknown or incomplete results remain inconclusive, and nested sheets are unchecked.

## Report presentation across Spaces

The user observed the report activating its previous desktop when inspection was requested elsewhere, immediately invalidating the observation. The report now uses public AppKit `moveToActiveSpace` collection behavior to bring iTile’s own window to the current desktop. This does not move inspected application windows. The user confirmed the fixed presentation worked, then supplied Chrome-present and other-desktop snapshots. Earlier ambiguous observations remain excluded; the new result is limited to that reported scenario.
