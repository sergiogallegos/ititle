# P3 lab: real AX delay and recovery

The five-trial run on 2026-10-04 and separate active Stop/Quit checks support P3 for the local fixture scenario on arm64 macOS 27.0.1; see [measured evidence](validation.md). This is a scoped human-reviewed result. The lab does not automatically declare P3 passed or select production timeout defaults.

## Run

1. Build with `scripts/verify`, then `scripts/package-p3-lab`. This creates `dist/iTile P3 Lab.app` and **does not replace `dist/iTile.app`**.
2. Open the lab in Finder. Choose **Enable Accessibility…** and enable **iTile P3 Lab** in System Settings. This separate bundle needs its own permission; existing iTile permission is not reused. If an ad-hoc rebuild leaves a stale grant, quit the lab, remove/re-add this lab's entry, and reopen it.
3. Stay on one desktop and keep the Mac awake. Choose **Start 5-trial experiment**. Two disposable fixture windows appear. One deliberately pauses its own event loop for 1.5 seconds per trial. Existing application windows are neither inspected nor changed.
4. Wait for **Sampling complete** (usually tens of seconds, with a 10-second fixture-ready timeout and 60-second run watchdog). Then choose **Copy summary**. **Copy full report** additionally includes every redacted worker observation for diagnosis. Nothing is written to disk automatically.
5. On a separate run, try **Stop** during sampling and confirm the lab stays responsive and both fixture windows close. Quit from the lab menu or close its main window to exit. Copy a partial summary if Stop did not behave as expected. This manual action is separate from an uninterrupted timing run.

Do not grant permission to the helper executable; it only owns its own disposable window and never performs AX reads against another process. The lab is the reader. No Screen Recording, keyboard monitoring, private API, injection, or external package is used.

## Experiment design

- The lab launches two copies of its embedded, ad-hoc signed fixture helper as owned child processes, with parent-only stdin/stdout pipes. There is no network listener. A dedicated reader uses streaming POSIX reads so short ready/events are delivered before EOF; the launch display updates its ready count and heartbeat while waiting. Their stdout is a small bounded event protocol: ready, pause begin, notification post, pause end. EOF makes a fixture exit; lab Stop/Quit terminates only these owned processes without joining blocked IPC.
- A single dedicated production `WindowProbe` thread is created per fixture. The fixture itself intentionally sleeps on its own main thread to simulate an unresponsive app; the lab never executes synchronous AX calls on its own main thread or Swift cooperative executor.
- One baseline pair, then five delayed/control pairs and five recovery pairs are collected: 22 observations in an uninterrupted run. Each pair admits one request per worker. The fixture begin event triggers the paired reads. Its end event and both completed reads are required before recovery; recovery completes before the next pause is armed. Requests are not accumulated behind a stuck worker.
- Each actual AX handle uses the existing experimental 0.2-second messaging timeout. The report measures **AXWindows IPC** specifically, and separately measures the **whole request**, which includes queueing, other attribute calls, and cleanup. A single AX timeout is not a hard deadline for a complete inspection.
- Start/end monotonic timestamps for AXWindows and fixture pauses are included. `started-during-pause` refers to the whole request's submission; compare the actual IPC timestamps with fixture intervals before concluding that IPC overlapped the induced fault. A completed scan during a pause might reveal platform caching or different dispatch behavior; do not assume the intended fault produced an AX delay just because the fixture slept.
- Each recovery posts a synthetic public accessibility title-change notification from the fixture's own window without changing or reading any title. The opt-in diagnostic observer retains at most 64 fixture handles until worker teardown so identity cleanup after an enumeration timeout does not remove this instrumentation. Normal M1 inspection does not enable these extra notifications. Notification reporting captures only worker arrival time, not text.
- Observer arrival is correlated with the fixture's pre-post timestamp using the same host monotonic clock and a bounded one-second matching window. This is candidate correlation, not a notification-carried sequence ID; missing/unmatched events are reported as missing, never as zero lag. AX notification coalescing, notification registration failure, or scheduling can invalidate a measurement. The synthetic event is posted at the end of the pause; it measures post-to-observer delivery, not a notification sent from a blocked main loop during the pause.
- A nominal 50 ms timer samples the lab's own main-loop intervals. Gaps include OS scheduling, timer coalescing, and report rendering, so they are not direct proof of AX-induced UI stalls. Manual menu/Stop/Quit checks complement this evidence.
- The summary reports count, min, median, empirical nearest-rank p95, and max by lane/phase. Five samples per phase are a small descriptive set, not a statistically robust tail-latency claim. Negative/nonfinite data is rejected by the pure summary type. Raw AX result codes stay visible: healthy/recovery errors must not be mistaken for fast success.

## Review criteria

Confirm both baseline fixtures were actually discovered; actual delayed AX requests overlapped recorded fixture pauses; healthy/control calls remained successful; timeout return codes and durations are plausible for the explicit handle timeout; both workers recover; and Stop/Quit remain responsive. Investigate any failed recovery, unbounded wait, main-loop gap, or missing observer evidence. A watchdog result is an incomplete run, not a pass. No fixed threshold is promoted to a production guarantee based on this run alone.

The lab stops early if baseline windows are unavailable. Fixture exit and run watchdog failures remain visible. A lost Accessibility grant or worker error is preserved in raw reports. A five-trial real-AX run and separate Stop/Quit cleanup checks have been observed; other environments and broader workloads still require validation. Automated worker fault tests cover mailbox isolation and cancellation with fake reads; they do not substitute for this experiment.
